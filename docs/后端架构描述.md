# 后端架构描述

本项目采用混合式AI枢纽架构，坚持AI增强而非AI驱动的设计思路。AI仅负责内容生成，业务逻辑、存储、批改、统计全部由程序实现，关闭AI不影响基础系统使用。系统与大模型之间传输标准化JSON数据，便于缓存、校验与业务导入；独立渲染层将结构化数据转化为卡片、列表等用户界面，使用者看不到原始JSON。系统配套实现Redis额度管控、全局内容缓存、Qdrant-RAG知识增强、限流熔断、多层降级容错、AI内容收藏笔记等完整基础设施，在成本、稳定性和用户体验之间取得平衡，扩展性良好。

## 架构要点展开

1. **AI 增强而非 AI 驱动**：词灵AI 属于增强能力，不是系统核心依赖。当 AI 关闭、超时、
   异常时，背单词、艾宾浩斯复习、生词本、试卷、做题、游戏、统计全部正常工作，
   页面通过 `AiFallbackTip` 等组件优雅降级，绝不崩溃。
2. **基础释义零 AI 成本**：普通单词释义走 MySQL 词典 + Redis 热点缓存，
   完全不消耗 AI 额度，保证高频学习动作的低延迟与低成本。
3. **标准化 JSON 数据通道**：系统与大模型之间只传输结构化 JSON（`AiPromptConstant`
   4 套提示词强约束输出 Schema）；后端校验、缓存、入库，前端由 `AiRenderUtil`
   渲染层转成卡片/列表/折叠预览；用户永远看不到 `{}[]""` 原始 JSON，
   仅主动点击"保存/导入"按钮才提交原始 JSON 给业务导入接口（后端二次严格校验）。
4. **Redis 每日额度**：`ai:quota:{userId}:{yyyyMMdd}` 计数 + `expire` 实现每日自动重置；
   数据库仅异步统计，业务链路不查询库表额度，天然支持水平扩展。
5. **全局内容缓存**：相同 system+user 输入只调用一次大模型（Redis 24h 热点缓存 +
   阅读解析 MySQL 持久化缓存），显著节省 token 并加快响应。
6. **RAG 知识增强**：`RagSearchService` 通过千问 `text-embedding-v3` 模型把问题编码为向量，
   检索云端 Qdrant 集合 `ling-word-kb` 取 top4 知识点注入提示词，降低幻觉；
   检索服务不可用时自动降级为模型通用知识回答。
7. **限流熔断**：`AiRateLimitService` 实现系统级 QPS 限流与用户级 3 秒冷却；
   `AiService` 通过超时控制与重试机制对上游故障做熔断保护。
8. **多层降级容错**：额度不足/限流/AI不可用/格式异常分别对应
   `AiQuotaTip`、`AiFallbackTip` 等友好提示与降级路径，任何异常都不影响核心学习功能。
9. **AI 内容沉淀**：生词巩固包存入 `ai_review_content`，生词本可回看；
   自由答疑优质回答可收藏进 `ai_favorite`（我的AI笔记）；AI 试卷导入 `exercise_paper`
   后由 Java 后端自动批改并收录错题，形成"AI 生成 → 人工确认 → 业务闭环"的完整链路。
